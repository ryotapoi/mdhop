# ADR 0032: モジュールと SQL の責務

## 背景

CLI の入出力とリンクグラフの処理、schema と feature 固有 SQL の所有者を明確にし、変更時に必要なコードと検証をまとめて扱う。ファイル数や未来の可能性だけを package 分割の理由にしない。

## 判断

- CLI はフラグ解析・ルーティング・出力形式・エラー表示を所有し、DB 操作・リンク解析・パス解決を行わない。
- core はファイル解析・schema・リンク解決・index 構築更新・query を所有し、CLI フラグ解析・表示形式・`os.Exit` を扱わず CLI に依存しない。
- testutil はテスト用ファイルシステムのセットアップを担い、本番コードから利用しない。
- core が schema と共通 CRUD を所有する。feature 固有の選択・更新・削除、および join・order・limit・condition を含む SQL はその feature に置く。schema を変更するときは、影響する共通 CRUD・feature SQL・test を同じ変更で更新する。
- 未来の可能性だけで空に近い package や汎用 abstraction を作らない。一方、独立した概念の依存方向をコンパイラで固定する価値があるなら、小さくても分割してよい。
- 同居は責務名・公開 API・依存方向が明確な場合に限る。分割を見送っても公開 interface とテストで責務を保つ。

分割は、責務名と公開 API が安定し、依存方向を一方向にでき、SQLite / YAML / filesystem / CLI 表示の所有者を明確にできるかで判断する。近い backlog で同じ境界を繰り返し触ることや、誤った参照を package 境界で防ぐ価値も判断材料とする。

## 理由と帰結

ファイル数だけでは責務の独立性や誤依存を防ぐ価値を示せない。役割と依存方向を基準にすることで、不要な分割を避けつつ、現在の変更で守るべき境界を明確にできる。SQL の所有者を feature の変更箇所に合わせ、schema と利用側の不整合を同じ変更で確認する。
