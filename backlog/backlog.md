### v0.23.0

- [x] 不要な `mdhop paths` コマンドを削除する

  目的: 既知の Vault を指定して実効的な Vault・設定・DB のパスを返す機能は不要と判断したため削除する。保存済みキャッシュから削除候補を選ぶための一覧とは別の機能であり、その代替にはならない。

  対応: CLI のコマンド登録・help・専用実装・専用テストと、他に利用のない専用 core API を削除する。README 日英・要件・関連する現行 ADR の記述を更新する。他のコマンドが使う共通のパス解決と、`--vault`・`--db`・`--config` の配置指定は維持する。

  受入条件: `paths` がコマンド一覧・help からなくなり、実行時は既存の未知コマンドと同じ扱いになる。現行機能として案内する文書が残らず、他のコマンドの配置解決と既定キャッシュの動作が維持される。

- [ ] 既定キャッシュのフォルダ・使用量・生成元 Vault を一覧する

  目的: 利用者・エージェントが、溜まったキャッシュを見比べて残すものと削除するものを判断できるようにする。元の Vault のパスを思い出して指定する必要のない操作とする。

  対象: 現在の `XDG_CACHE_HOME`（未設定・空・相対パスなら `~/.cache`）の `mdhop/vaults/` 配下に実在する hash フォルダを列挙する。各項目はキャッシュフォルダの絶対パス・フォルダ全体のディスク使用量・生成元 Vault の絶対パスを返す。使用量は DB 本体だけでなく SQLite 補助ファイル・一時ファイル・生成元の記録を含め、一覧表示時に測定する。補助ファイル等を別項目として数えない。

  生成元の記録: `--db` を省略して既定キャッシュへ索引を生成するときだけ、同じ hash フォルダの `origin.json` へ `{"vault":"/absolute/vault/path"}` を保存する。`--db` を明示した場合は、指定先の場所によらず `origin.json` を作成・更新しない。値は hash の算出に使う絶対パス化・symlink 解決後の Vault root とする。hash から逆算せず、生成時に記録する。容量・存在状態・最終利用日時や全体の対応表は保存しない。Vault の移動・削除後も生成時のパスを保持し、キャッシュフォルダの削除で記録も一緒に消える。既存キャッシュで記録がないものは `--db` を省略した再 build で付与し、それまでは生成元不明として一覧に含める。

  出力: 通常の text は項目ごとにキャッシュフォルダの絶対パスを先頭行、その下に `size: 120 MiB  original: /absolute/vault/path` のように読みやすい単位の使用量と生成元を表示し、項目間を空行で区切る。`--format json` は `cache_path`・`size_bytes`・`vault` を持つ項目の配列を返す。`size_bytes` は表示用に丸める前のディスク使用量をバイトで返す。生成元の記録がなければ text は不明と表示し、JSON の `vault` は `null` とする。コマンド名・一覧順序・使用量の測定定義は CLI ヘルプとテストで定める。

  境界: `--db` で指定された外部 DB の登録・追跡・横断探索はしない。過去の `XDG_CACHE_HOME` の探索、Vault の移動先探索、削除機能・自動削除・手動削除の監視は追加しない。一覧操作でディレクトリ・DB・生成元の記録を作成・更新せず、キャッシュがなければ空の一覧を返す。

  受入条件: Vault を指定せずに複数のキャッシュの場所・使用量・生成元を一覧できる。使用量は現在のフォルダ内容を反映し、生成元の記録がないキャッシュや Vault が移動・削除されたキャッシュも表示できる。キャッシュフォルダを手動削除すると次の一覧から消え、別の管理情報の更新が不要である。text / JSON の出力、空の一覧、一覧操作の無変更性を確認する。README 日英・CLI ヘルプ・関連する現行 ADR を更新し、キャッシュは再生成可能で、mdhop が使用していないときにフォルダごと削除し、必要時に build で再生成できることを説明する。

- [ ] resolve に任意の行番号を指定し、索引のリンク出現を選択する

  目的: [ADR 0035](../decisions/0035-line-qualified-resolve.md)の採用判断に従い、同一ノートの同じ raw が表内外で異なる意味を持つ場合にクリックした行の解決先を返す。v0.22.0 の採否調査とは独立した未実装タスクで、v0.23.0 に含める。

  契約:

  - `resolve --from <vault-relative-note> --link <indexed-raw-text> --line <positive-integer>`。`--line` は任意で、明示時は 1 以上の整数だけを許す。0・負数・整数でない値は引数エラーとし、省略と明示 0 を区別する。
  - 行はファイル先頭を 1 とする元の物理行番号で、frontmatter も数える。表示上の行・折返し行ではない。現在の単一行本文リンクの出現行、索引の `line_start` への完全一致を用い、範囲包含・近傍探索はしない。参照リンクは定義行でなく使用箇所の行を指定する。
  - 指定時は正規化された元ノート・`raw_link` の完全一致・`line_start` の一致を満たす edge だけを選ぶ。呼び出し元は escape / alias / embed / fragment / 空白を勝手に除去・正規化しない。タグ等も含め、既存索引の `raw_link` 表現は変えない。
  - distinct な `target_id` と `COALESCE(subpath, '')` の組が一つなら成功し、同じ組の複数出現も成功する。異なる target または subpath が複数なら `ErrAmbiguousLink`、ゼロ件なら `ErrLinkNotFound` 相当の解決エラーとする。別行・再解析・正規化照合へフォールバックしない。source 未登録等の既存エラー処理は維持する。
  - 省略時は既存の完全一致優先、異なる索引意味の拒否、完全一致がない場合の既存再解析照合を維持する。既存の出力項目と text / JSON の形を維持する。
  - 呼び出し元は同じ Vault / DB を選び、索引作成時と同じ保存済み本文から元ノート・raw・物理行を取得する。保存後に `build` または適切な `update` / `add` 等を完了し、位置を取得し直す。参照定義・表境界の編集も索引更新が必要で、設定・解析規則の変更時は `build` する。未保存 buffer、原文へ逆対応できない renderer、行移動後の古い索引には正しいクリック先を保証しない。
  - 行と原文の一致だけでは本文と索引の同一世代を証明できない。位置取得から解決まで本文・索引を変更しないことを利用条件とし、本文再読・mtime/hash 検査・世代 token・自動更新・排他制御や並行編集・更新をまたぐ snapshot 保証を追加しない。

  実装範囲: `cmd/mdhop/resolve.go` の flag 解析・help、README 日英、`internal/core/resolve.go` の位置指定経路・feature SQL、対象 core / CLI テスト。core API の具体的なシグネチャは既存 caller と `Locations` の互換性を確認して選ぶ。schema・parser・dispatcher・列/offset API・呼び出し元 UI / renderer は変更しない。frontmatter や未対応の複数行文法の保証も広げない。

  受入条件: 表内外の同一 raw を行別に解決でき、frontmatter を含む物理行番号と参照リンクの使用行を扱う。同一行の同結果の重複は成功し、異なる target / subpath は拒否する。raw 不一致・行不一致は別行や再解析に逃げずエラーになる。無効な `--line` と明示 0 を拒否する。行省略時の既存互換、本文を編集しても未更新なら索引 snapshot に依存する挙動、既存 text / JSON 形をテストする。同一行の異なる意味を通常の parser で生成できなければ core の索引 fixture で確認し、文法を拡張しない。

  検証: [検証手順](../docs/verification.md)の core / CLI 変更 gate に従い、集中テスト、`go test ./...`、`go build ./...` と実バイナリの正常系・異常系（stdout・stderr・終了コード・file / DB の副作用）を確認する。help / README に物理行・原文・索引整合の利用条件を記載する。

### v0.24.0

- [ ] Markdown link を元ノート相対、先頭 `/` を Vault ルート基準で解決する

  目的: 一般的な Markdown 文書と GitHub のリポジトリ内 Markdown に合わせ、ディレクトリを省略したリンクも元ノートと同じディレクトリを指すようにする。後続の差分更新で Markdown link の依存先をパスで扱えるようにする。wikilink の Vault 内探索・basename 解決・ルート優先・曖昧性拒否は現行のままとする。

  契約: Markdown link の `to.md` と `./to.md` は同じ参照先とする。`path/to.md`・`./path/to.md`・`../to.md` は元ノートのディレクトリを基準に解決し、`/path/to.md` は Vault ルート基準で解決する。Markdown link を basename で Vault 全体から探したり、相対パスが存在しない場合に Vault ルートへフォールバックしたりしない。参照リンクの定義先と画像・asset のリンクにも同じ規則を適用する。外部 URI、同一ノートの fragment、URL decode と escape、alias・embed・subpath の既存の意味保存と Vault 外参照の拒否は維持する。frontmatter の raw path 値の解釈は変更しない。

  対応: parse / resolve と、move・convert・repair・simplify 等のリンク生成・書換え経路を新ルールに揃える。索引の解釈 version を更新し、旧索引は全量 build で再生成する。README 日英・CLI help・要件・関連する現行 ADR を更新し、従来の Markdown basename / Vault 相対リンクは解釈が変わることを説明する。wikilink への自動変換や互換モードは追加しない。

  受入条件: サブディレクトリの元ノートから `to.md` と `./to.md` が同じディレクトリへ解決され、他のディレクトリの同名ファイルに影響されない。`path/to.md`・`../to.md`・`/path/to.md`、参照リンク・画像・未作成参照先を確認する。move と形式変換で参照先の意味が維持され、wikilink の既存動作は変わらない。旧索引の拒否と全量再生成を確認する。

- [ ] build に変更検出を含む自動差分更新を実装する

  目的: 利用者が更新対象を列挙せずに索引を最新化でき、繰り返しの build で未変更ファイルの不要な読み取り・解析を減らす。自動差分更新の採用を再判断する調査ではなく、上記の Markdown link 解釈変更後に実装するタスクとする。

  対応: ファイル一覧とファイル別の保存情報を使って追加・変更・削除を検出し、索引へ反映する。「前回 build 時刻より mtime が新しいファイルだけ」では判定しない。既存の status と update / add 等を確認し、build の操作・変更検出規則・全量再生成を明示する方法を着手時に確定する。mtime を保持した変更・復元、同一秒の変更、build 中の変更について保証できる範囲を明記する。

  整合性: Markdown link は上記の相対パス規則で扱う。wikilink は参照先の追加・削除や basename 衝突により未変更ノートでも解決結果が変わるため、影響する既存リンクを再評価し、全量 build と同じ関係を保つ。実際に basename 解決へ依存するリンクがない場合は、その再評価を省けるようにする。パス参照先の追加・削除による実在状態の変更は反映する。設定・解析規則・索引形式の変更時と索引が存在しない場合には全量再生成できるようにし、旧新の解釈を混在させない。全量再生成へ戻す条件と設定変更の扱いは着手時に確定する。現行 build の失敗時の旧 DB 保持と、参照側に完成済み索引を見せる性質を維持する。

  受入条件: 無変更・本文変更・追加・削除・移動について差分更新後の索引が全量 build と意味的に一致する。未作成参照先の実在化・削除、wikilink の同名衝突とルート優先の変化を確認する。変更検出の限界、全量再生成の操作と条件、失敗時の無部分更新を確認する。代表的な Vault と規模・本文量・変更割合を変えたケースで全量方式と比較し、変更検出のコストを含む測定条件と結果を記録する。README 日英・CLI help・要件・関連する現行 ADR を更新する。

- [ ] wikilink 無効化設定による差分 build の高速化を検証し、効果がある場合に導入する

  目的: Markhop で開発リポジトリ等を開き、関連探索のための索引を頻繁に再構築するが、wikilink は使わない用途を想定する。本文と通常の Markdown link の閲覧だけなら索引生成自体を不要とする既存の Markhop の動作で足り、この設定の対象ではない。wikilink の構文検出を省くこと自体ではなく、wikilink を扱わないと明示することで差分更新時の依存確認・再解決を減らし、繰り返しの build を速くする。上記の Markdown link 解釈変更と自動差分更新の後に評価する。設定なしの差分更新で同じ速度を達成できる場合など、実用上の速度差がなければ設定は導入しない。

  比較: wikilink を含まない代表的な開発リポジトリで、全量 build、設定なし・wikilink 有効の差分 build、明示無効の差分 build を比較する。無変更・本文変更・追加・削除・移動、規模と変更割合を変え、変更検出も含む所要時間と省けた読み取り・解析・依存確認を記録する。無効化を宣言した場合だけ省ける処理を特定し、既存の自動差分更新への改善で同じ効果が得られないかも確認する。

  採用時の契約: config なしと config あり・キー省略はともに wikilink 有効とし、明示設定でのみ無効化する。設定キー名は着手時に決める。無効時は本文・frontmatter の wikilink と embed をリンクとして索引化せず、リンク書換えの対象にもしない。Markdown link・画像・asset は上記のパス規則で扱う。frontmatter の raw path 値をリンク化する `meta.link_keys` は別の設定であり、裸の名前による basename 依存がある場合は必要な再評価を残す。無効化だけで全リンクがパス参照になるとは仮定しない。build・update・add・resolve・書換え経路で同じ実効設定を使い、設定切替時は全量再生成して索引の解釈を混在させない。

  案内: 採用時は README 日英の設定欄と build の CLI help に、wikilink を使わない場合の設定例・失われるリンク関係・差分更新で省ける処理を記載する。`init-meta` は frontmatter 型定義の生成という責務を維持し、help と生成 TOML のコメントから設定例を案内する。高速化の説明は実測結果に即した範囲にする。Markhop が専用設定を渡して利用できる契約を明確にし、Markhop 自体の変更はこのタスクに含めない。

  完了条件: 測定条件・結果と採用 / 見送りの理由を記録する。採用時は config の3状態、無効時の非索引化、設定切替時の全量再生成、raw path の basename 依存が残る場合を確認する。同じ実効設定の全量 build と差分 build が意味的に一致し、想定用途で設定なしの差分 build に対する実用上の速度改善が確認できること。見送り時は無効化設定とその案内を残さない。

各タスクの検証は [検証手順](../docs/verification.md)の core / CLI 変更 gate に従う。
