#### レビュー対応

- [x] ディレクトリ操作で大小文字の異なる別フォルダーを選ばないようにする（A3-01）
  - 問題: `internal/core/db.go` の `listDirNodesByType` が SQLite の `LIKE` を使い、`docs/` を指定しても `Docs/` 配下を選ぶ。両者が別フォルダーとして存在する環境では、指定外ファイルの削除・移動につながる。
  - 対応: 大小文字を区別する literal prefix 選択に揃える。SQL と Go に二重の選別規則を置かず、共通のディレクトリ選択処理で保証する。
  - 完了条件: `docs/` と `Docs/` が共存しても指定した側だけが削除・移動の対象になる。Unicode・`%`・`_` を含むパスと、note/asset の既存選択契約を維持する。

- [x] set が YAML anchor / alias を壊して成功しないようにする（A11-C1）
  - 問題: `status: &state draft` と `copy: *state` を持つノートで status を更新すると、独自の行置換が anchor を消し、未定義の alias を残す。不正 YAML を保存したまま成功し、索引の属性も消える。
  - 対応方針: `yaml.v3` が解析する anchor / alias の関係に編集処理を合わせる。ライブラリ側の未対応を独自の YAML 実装で補うことは求めない。mdhop が更新を保証しない構文は変更前に未対応として拒否してよい。
  - 完了条件: 有効だった YAML を壊して成功しない。対応する更新では、対象外 key の値・参照の意味を保ち、索引を更新する。未対応として拒否する場合は元ファイルと索引を保持する。共有値を持つ anchor の更新成功まで保証するかは、着手時に既存の単一 key 更新契約と照合して決める。
  - 判断: 単一 key 更新契約を保つため共有 anchor の更新成功は保証せず、対象 key / 値の anchor・alias、anchor 付き root、alias key は保存前に拒否する。独立 key の更新・追加は維持する。

- [x] set のリスト更新を YAML ライブラリの解析と一致させる（A11-C2）
  - 問題: `aliases: [don't,`、次行の `old`、独立行の `]` という有効な flow sequence を `--list` で更新すると、`internal/core/set.go` の独自走査が単語中の apostrophe を引用符の開始と誤認する。余分な `]` を残し、YAML と索引の属性を壊して成功する。
  - 対応方針: ライブラリが正常に解析している構文を mdhop の編集処理が誤解釈する部分を直す。ライブラリ側の未実装を補う独自文法対応は求めない。
  - 完了条件: 上記の有効なリストを指定した新リストへ正常に更新でき、対象外の属性・タグ・リンクと既存のコメント保存契約を維持する。保存前の再解析による破損防止だけでは、このタスクを完了にしない。A11-C1 と共通の保存前検証を設ける場合も、ライブラリの解析を再利用する。

- [x] frontmatter raw path の相対参照を move 前の意味変更検査に含める（A5-2）
  - 問題: `[meta] link_keys = ["related"]` を設定し、`old/Source.md` の `related: ./Missing.md` が未解決の場合、`new/Source.md` への移動が検査を通る。`new/Missing.md` が存在すると、値を変更せず参照先の意味が変わる。通常の frontmatter wikilink とは別の、設定した raw path に限る問題。
  - 対応: ADR 0037 の「raw path の意味が変わる操作は実行前に拒否する」検査を、未解決の元ノート相対参照にも適用する。自動書き換え規則は追加しない。
  - 完了条件: 上記の移動をファイル・索引の変更前に拒否し、意味を維持できる移動は引き続き許可する。既存の検査を共用し、参照種類による検査漏れをなくす。

- [x] Add の frontmatter raw path 検査で添付参照から生じる曖昧性を拒否する（A5-3）
  - 問題: `[meta] link_keys = ["related"]` で `related: LICENSE` が実在添付 `LICENSE` を指す状態に、`x/LICENSE.md` と `y/LICENSE.md` を追加すると Add が成功する。その後の build はノート候補が曖昧として失敗する。
  - 対応: 既存の曖昧性検査を実在添付へ解決している raw path にも適用する。ノート優先・一意候補への解決・同名 root ノート優先・root 不在の複数候補は拒否、という既存規則に揃える。
  - 完了条件: 上記の曖昧性を生む Add を索引変更前に拒否し、Add と build の判定を一致させる。一意候補と root 優先の既存挙動を保ち、解決規則を二重実装しない。

- [x] disambiguate が未解決の指定パスを別パスの同名ファイルへ付け替えないようにする（A10-C2）
  - 問題: `excluded/A.md` を `build.exclude_paths` で除外し、対象内に `sub/A.md` があるとき、build は `[[excluded/A]]` と `[A](excluded/A.md)` を未解決として扱う。一方、disambiguate は名前だけで `sub/A.md` を選び、そこへのリンクに書き換える。DB モードと `--scan` の両方で再現する。
  - 対応方針: 除外後のリンク解決で指定先が見つからないパスリンクは、未解決のまま保持する。別パスの同名候補への付け替えを行わず、build と disambiguate の解決規則を揃える。除外ファイルを実在確認によって候補へ戻す修正ではない。
  - 完了条件: 上記の両リンクは DB / scan のどちらでも変更されない。`[[A]]` のような裸名が除外後の一意候補 `sub/A.md` に解決する場合は、その参照先を保って明示化できる。関連する CLI 説明・テストに従来の付け替え動作が記されていれば、この方針と整合させる。
  - 保守性・頻度・リスク: build と共有できる解決規則を優先する。指定先が除外され、別パスに同名候補がある状態で disambiguate を実行すると発生する。頻度は未測定だが、ノート本文を別の参照先へ変更するため修正対象とする。
