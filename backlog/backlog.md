## タスク

### v0.25.0

- [x] query に関連を示すリンクの位置を返すオプションを追加する
  - 目的: Markhop が Backlinks や 2-hop のノートを開いたとき、リンクが書かれている箇所へ移動できるようにする。既存の `--include-snippet` は行単位で、対象に索引作成後の編集が1件でもあると問い合わせ全体が失敗するため使えない。
  - 対応: `query --include-location` を追加し、Backlinks はそのノートが入口を指す最初の箇所、2-hop はそのノートが経由先を指す最初の箇所の、開始・終了の位置とリンクの原文を返す。索引の形式は変えず、返すときに対象ファイルを読み、索引の行とリンクの原文から列を求める。
  - 位置の形式: `{"start":{"line":12,"column":8},"end":{"line":12,"column":11}}`。行・列は1始まり、列は原文の Unicode コードポイント単位、終端はその位置を含まない。行は frontmatter を含む物理行とし、CRLF は改行1つとして数える（Markhop のコメントと同じ）。
  - 完了条件: 上記の位置と原文を返す。対象ファイルが索引作成後に編集・削除されていて位置を確定できない場合も問い合わせは成功し、そのノートだけ位置なしで原文を返す。frontmatter 内のリンクには位置を返さない。指定しない場合の出力は変わらず、本文を読まない。

- [x] 未リンク言及を探す mentions コマンドを追加する
  - 目的: リンクしていないが名前が書かれているノートを、Markhop と Agent が明示的に探せるようにする。全ファイルを読むため、索引と限定的な読み取りで完結する query とは別コマンドにする。
  - 対応: `mdhop mentions --file <path>` は「入口の名前が書かれているノート」と「入口の本文に書かれている既知のノート名・未作成リンク名」の両方を返す。`mdhop mentions --phantom <name>` は前者だけを返す。2-hop は扱わない。
  - 一致規則:
    - ノート名（拡張子なし）と未作成リンク名を対象とし、大文字小文字を区別せず、Unicode は NFC に揃えて比べる。1文字の名前も対象とする。
    - 既定では英字の途中に当てない（`git` は `github` に当てない）。数字・カタカナ・漢字との境目は見ない（`ios` は `iOS26`、`スキル` は `スキルアップ`、`仕様` は `仕様書` に当てる）。`--partial` を付けると英字の途中にも当てる。
    - frontmatter、コードフェンス、インラインコード、wikilink・Markdown リンクの中、URL には当てない。
    - 入口自身と、既にリンクしている相手（入口へリンクしているノート、入口からリンクしている先）は返さない。同名のノートが複数あればすべて返す。
    - `[query.hide]` に従う。
  - 出力: 1ノート1件とし、最初に見つかった箇所の位置・一致した原文・抜粋を付ける。位置は query の `--include-location` と同じ形式とし、NFC に揃える前の原文で数える。方向ごとの総数を常に返す。`--limit` を任意で受け付け、省略時は全件とする。`--offset` は付けない。
  - 完了条件: 上の規則を例題テストで固定する。Knowledge で件数・雑音・応答時間を確かめ、規則の見直しが要るかを判断する。
  - 結果（2026-11-26）: Knowledge（4,259ノート）で1回平均0.21秒・最大0.75秒。件数は vault 規模と名前の一般性に比例し、雑音（同名ノート全件・短い未作成リンク名の日本語内一致）は規則どおりの挙動のため規則は見直さない。件数への対処は出力を絞るオプションで行う（次項）。

- [x] mentions に結果を絞るオプションを追加する
  - 目的: mentions の件数は vault の規模と名前の一般性に比例して増え、規則では減らせない。利用者が置き場所や種類で結果を絞れるようにする。Knowledge では `Bee` の言及819件のうち日報（daily-reports・daily）が710件、外向き580件のうち未作成リンク名が206件で、「キル」「質」「md」など日本語や拡張子の途中に当たるものはすべて未作成リンク名だった。
  - 対応:
    - `--path <glob>`（繰り返し可）: 結果のノートを、いずれかの glob に一致する path に限る。`--hide-path <glob>`（繰り返し可）: 一致する path のノートを結果から除く。意味と glob の書き方は query の同名オプションに合わせる。
    - `--no-phantom`: 未作成リンク名を結果から除く（外向きのみに効く）。
  - 完了条件: 各オプションの絞り込みと、`[query.hide]`・`--limit`・方向ごとの総数との関係（総数は絞り込み後の件数か）を決めて例題テストで固定する。指定しない場合の出力は変わらない。
  - 結果（2026-11-26）: 3 オプションとも両方向の候補選定で効き、方向ごとの総数は絞り込み後・`--limit` 前の件数とする。`--hide-path` は `[query.hide]` に合算し、`--path` と両方に一致するノートは除く。未作成リンク名は path を持たないため `--path`・`--hide-path` では除かず、`--no-phantom` だけが除く。glob の書き方と `[` の拒否は query と同じ。

- [x] mentions にメタデータで結果を絞る `--where` を追加する
  - 目的: 置き場所や種類では区別できない条件（`status != stale`、`type == concept` など）で mentions の結果を絞れるようにする。
  - 対応: `--where <expr>`（繰り返し可、AND）を追加する。式の書き方と、未作成リンク名など frontmatter を持たない結果の扱いは query の `--where` に合わせる。他の絞り込みと同じく候補選定で効かせ、方向ごとの総数は絞り込み後・`--limit` 前の件数とする。
  - 完了条件: 両方向での絞り込み、frontmatter を持たない結果の扱い、`--path`・`--hide-path`・`--no-phantom`・`--limit` との組み合わせを例題テストで固定する。指定しない場合の出力は変わらない。
  - 結果（2026-11-26）: 両方向の候補選定で効き、方向ごとの総数は絞り込み後・`--limit` 前の件数とする。式の解析と条件は query と同じで、指定時は未作成リンク名を常に除き、該当キーを持たないノートは `key = v`・`key != v`・比較・`~` では除かれ、`key NOT EXISTS` では残る。`--path`・`--hide-path`・`[query.hide]`・`--no-phantom` とは AND で合成する。

- [x] mentions に返す方向を選ぶ `--relations` を追加する
  - 目的: `--file` 入口で、入口の名前が書かれているノート（incoming）か、入口の本文に書かれている名前（outgoing）の片方だけを見たいときに、もう片方を返さないようにする。
  - 対応: `--relations <list>` を追加し、値は `incoming,outgoing` のカンマ区切りとする。省略時は両方。オプション名と、選ばなかった方向の出力上の扱い（項目を出さない／総数の扱い）は query の `--relations` に合わせる。出力の項目名 `incoming` / `outgoing` は変えない（言及はリンクではないため backlinks と呼ばず、`incoming` は search の `--no-incoming`・`incoming_count` で既にある語）。`--phantom` 入口で `outgoing` を指定した場合の扱いも決める。
  - 完了条件: 各値の組み合わせ、不正な値、`--phantom` 入口との組み合わせ、`--limit` との関係を例題テストで固定する。指定しない場合の出力は変わらない。
  - 結果（2026-11-26）: 値の解析と不正値（空・未知・重複）は query と同じで、索引を開く前に検証する。選ばなかった方向は JSON の配列と `total` 内の件数、text の節と `total:` 下の行をいずれも出さず、計算もしない。`--phantom` 入口で `outgoing` を含めるとエラー（`relations: outgoing requires a --file entry`）とし、`--phantom --relations incoming` は未指定時と同じ出力になる。`--limit` は query と違い単一方向の指定を求めず、選んだ方向ごとに効き、`total` は選んだ方向だけ絞り込み後・`--limit` 前の件数とする。

- [x] mentions に並び順を指定する `--sort` を追加する
  - 目的: 言及の多いノートで、新しいものなど見たい順に結果を並べ、`--limit` と組み合わせて上位だけを見られるようにする。既定はパス順で、日付入りの日報では古い順になる。
  - 対応: `--sort <key|-key>` を追加し、指定できるキー、`-` による降順、キーを持たない結果（未作成リンク名、frontmatter にそのキーがないノート）の位置、同順位の並びは `search --sort` に合わせる。並べ替えは絞り込みの後・`--limit` の前に行う。
  - 完了条件: 昇順・降順、キーを持たない結果の位置、`--limit` との組み合わせ、不正なキーを例題テストで固定する。指定しない場合の出力は変わらない。
  - 結果（2026-11-26）: キー（frontmatter のキーと `lines`・`outgoing_count`・`incoming_count`）、`-` による降順、複数値の昇順は最小値・降順は最大値、未知のキーの受理、`--sort -` のエラー（`empty sort key`、索引を開く前）は search と同じ。方向ごとに絞り込み後・`--limit` 前に並べ、`total` は変わらない。キーを持たないノートと未作成リンク名（計算フィールドでも値を持たない）は昇順・降順とも末尾に置き、同順位とキーなし同士は既定のパス順（未作成リンク名はノートの後ろで名前順）とする。

- [x] search と mentions の `--sort` でファイルの更新日時（mtime）を使えるようにする
  - 目的: frontmatter に `updated` を書かない vault（開発プロジェクトの md など）でも、最近更新したノートから並べられるようにする。
  - 対応: `--sort` のキーに mtime を表す計算フィールドを追加する（名前は既存の計算フィールド `lines` などとの整合で決める）。値は索引に保存済みの mtime を使い、本文やファイルを読まない。そのため最後の build / update 以降の変更は反映されない。
  - 完了条件: search と mentions の両方で昇順・降順を例題テストで固定し、help に索引時点の値であることを書く。既存のキー（同名の frontmatter キーを含む）の挙動は変わらない。
  - 結果（2026-11-26）: キー名は索引の列名どおり `mtime` とし、search と mentions で共通に使える（`--sort` 専用で `--fields` には加えない）。値は最後の build / update（add・move などの索引更新を含む）時点の秒単位の mtime で、並べ替え時にファイルを読まない。同じ秒のノートは既定のパス順、未作成リンク名は昇順・降順とも末尾。計算フィールドは同名の frontmatter キーより優先する既存の規則により、frontmatter に `mtime` キーを持つ vault では `--sort mtime` が frontmatter の値ではなく索引の mtime で並ぶ。それ以外のキーの挙動は変わらない。

- [x] `--sort` で frontmatter のキーを `meta.<key>` と書くようにする（破壊的変更）
  - 目的: `--sort` のキーは frontmatter のキーと計算フィールド（`lines`・`outgoing_count`・`incoming_count`・`mtime`）を同じ書き方で受け付けるため、同名の frontmatter キーが計算フィールドに隠れる（frontmatter の `mtime` や `lines` では並べられない）。また未知の名前を黙って frontmatter のキーとして扱うため、打ち間違いがエラーにならない。frontmatter のキーを `meta.<key>` と書く `--fields` と規則を揃え、衝突を仕組みでなくす。
  - 対応: search と mentions の `--sort` で、計算フィールドは名前だけ（`--sort -mtime`）、frontmatter のキーは `meta.<key>`（`--sort -meta.updated`）と書く。どちらでもない名前だけのキーはエラーにする。`-` による降順、キーを持たない結果の位置、同順位の並びなど、並べ方は変えない。frontmatter のキーしか扱わない `--where` は名前だけのまま変えない。
  - 完了条件: search と mentions の両方で、計算フィールド・`meta.<key>`・名前だけの未知のキー（エラー）・計算フィールドと同名の frontmatter キー（`meta.mtime` で frontmatter の値で並ぶ）を例題テストで固定する。help と既存テスト・例の `--sort` の書き方を新しい規則に合わせる。
  - 手がかり: キーの振り分けは `internal/core/search.go` の `computedSortColumn`・`parseSortKey`（mentions も同じ関数を使う）、`meta.<key>` の扱いは同ファイルの `wantMetaFields`。版を切るときに CHANGELOG へ破壊的変更として書く。
  - 結果（2026-11-26）: 両コマンドで未知の裸名と空の `meta.` を索引を開く前に拒否し、エラーで `meta.<key>` の書き方を案内する。索引にないキーも `meta.<key>` で指定できる。`mtime` と `meta.mtime` がそれぞれ索引の更新日時と frontmatter の値で異なる順に並ぶことを例題テストで確認した。
