# mdhop の要件

## 目的と対象

mdhop は、Obsidian Vault 相当の Markdown リポジトリを事前解析し、Coding Agent と CLI 利用者が grep を乱用せず関連ノートへ辿るための CLI である。リンクグラフから次に読むべきノートを見つけ、必要な属性と最小限の本文だけを返して探索のコンテキストを抑える。

- 対象は Vault 配下の Markdown ノートと、画像・PDF 等の非 Markdown ファイル（asset）。wikilink、Markdown link・参照リンク、タグ、frontmatter による関係を扱う。
- 実在しないリンク先も phantom として扱い、未作成の概念への参照元を探索できるようにする。
- ローカルの SQLite で完結する。ノート・asset の識別と出力に使うパスは Vault 相対・forward slash・Unicode NFC に正規化し、OS のパス表現に依存させない。

## 正しさと安全性

- Obsidian のリンク・タグの意味を保つ。alias、subpath、embed を壊さず、コードフェンス・インラインコード内のリンクやタグ等の誤検出を抑止する。対応する文法の範囲と約束は実装・テスト、利用者向けの引数と使用例は CLI ヘルプが持つ。Obsidian / CommonMark 全文法への準拠は目標にしない。
- 曖昧なリンクは静かに候補を選ばずエラーにする。basename の衝突そのものを禁止せず、明確なパスやルート優先によって一意に解決できるリンクは許す。
- wikilink の basename をできるだけ短く使いながら、衝突や移動で意味が変わる場合だけ書き換えて元の参照先を維持する。表記が一意に戻った際の短縮は明示操作とし、通常の更新で Git 差分を揺らさない。
- Markdown link・参照リンク定義・画像・asset は元ノート相対で解決し、先頭 `/` は Vault ルート基準とする。裸名の Vault 全体探索やルートへのフォールバックを行わず、wikilink と frontmatter raw path の解釈は独立して維持する。
- 書き換えは参照先と表示の意味を保存する。自動書き換えできない参照定義や frontmatter の raw path 値の意味を変える操作、予定した YAML source と値の対応を証明できない操作は、変更前に拒否する。
- ノート mutation は Vault 外への書き込み・削除と意図しない上書きを拒否する。書き込み候補の末尾ファイルと祖先ディレクトリが symlink 経由で外部を指す場合も拒否し、複数候補の操作では外部候補を含んだまま部分実行しない。復元時も外部書き込みを拒否し、復元失敗を報告する。Vault 内 symlink と symlink の Vault root は利用できる。意図的な並行 symlink 差替えと hardlink はこの保証の対象外である。

## 読み取りと書き換えの区分

区分の軸は Vault の Markdown ノートを書き換えるかどうかとする。build / update 等による内部 index DB への書き込みと、設定ファイルの変更はこの区分の対象外である。

- 参照系はノート本文を変更せず、索引から解決・探索・診断する。
- ノートを書き換える操作は意味保存と安全性を優先し、必要なイベント時に明示的に実行する。

## 関連探索と省コンテキスト

- 入口へのリンク元、入口からのリンク先、共通のリンク先を持つ別ノートを探索できるようにする。通常は一度に全件返し、必要なときだけ関係を選び、単一関係でページ取得する。既定上限や経由先ごとの件数制限で関連を落とさない。
- 関連対象の表示と、関連を発見する経由先の選択を分ける。経由先を表示から隠しても、そこを通じて発見した対象は残す。表示条件は構造化した対象・経由先に適用し、生の本文プレビューの全文検閲は行わない。
- ノート一件の属性取得は関連探索から分ける。関連先の本文冒頭と関係の根拠箇所は、必要なときだけ追加する。
- DB に Markdown 本文を保存しない。本文プレビューは必要なファイルだけから読み、索引の位置情報と現在の本文が一致しない場合はエラーにする。非表示・ページ外・先読み・未選択関係の不要本文を読まない。
- 関連探索の非目標は、query と inspect を束ねる一括 script、query の count 専用機能、複数関係への共通ページ、入口の見出し抽出・自動要約、実行間の index 同時更新保証である。

## インターフェースと内部 index

- stdout の JSON は agent 向けの安定インターフェースとして扱い、単独で parse できるようにする。警告等の付加情報は stderr に出す。text は利用者や LLM が読みやすい出力とする。
- 内部 index は再生成可能な派生物として扱い、通常はコミットしない。生成物を手編集せず、生成ロジックを変更する。
- 永続形式・リンク解釈を変える場合、既存 index の in-place migration は行わず build で再生成する。旧新の解釈を partial update で混在させない。
- build は追加・変更・削除を自動検出し、未変更ノートの本文読み取り・解析を省く。静止した Vault では全量再生成と意味的に同じ索引を公開する。`build --full` は全量読み取り・解析・再生成を明示する。update は指定ファイルの差分更新とし、query / resolve は index と必要時の限定的なファイル読み取りで完結させる。
- build はファイル別 nanosecond mtime と size の等値比較を使い、前回 build 時刻との大小で判定しない。同一 mtime・size の編集・復元と filesystem の時刻分解能以下の同サイズ変更は保証せず、全量再生成で復旧する。
- 初回・旧形式・保存情報欠落・索引に影響する実効設定または canonical Vault root の変更・既存 index mutation 後は全量再生成する。追加・削除に影響される既存リンクは本文を解析し直さず再解決する。
- 差分・全量とも完成した索引を原子的に公開し、失敗時は旧 DB を保持する。読み取り前後と公開前の一覧・署名で検知した入力変動は失敗にする。filesystem snapshot / lock は保証せず、最終確認後の編集や同一署名への復元を完全検知しない。
